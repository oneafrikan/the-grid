## Enforcement ladder

Each level catches what the one below cannot and is weaker than the one above it. Built-by shows which change delivers it.

| Level | Mechanism | Catches | Does not catch / bypass | Built by |
|---|---|---|---|---|
| L0 | Advisory prose: `AGENTS_base.md` fragment (stages, warrant rule, how to file) + `CLAUDE.md` trailhead | An agent that reads and follows it | An agent that does not read it; lean-profile agents never see the fragment (Risk 4) | A1 |
| L1 | Template: the signal template | A signal missing a field, written by someone using the template | Free-form files; a template can be ignored | A2 |
| L2 | Optional Stop hook `epistemic-stop.sh` (profile `strict`, fails open) | A completion claim with no RAN/READ/UNTESTED, once per turn | A wrong warrant; a claim phrased outside the regex; hook off; non-terminal clients | this change |
| L3 | CI lint: `map.py --check` in `gate.sh` (stage enum, signal frontmatter, warrant on promoted entries, canon placement, address resolution); canon changes only through a PR (CODEOWNERS, template checkbox, `next` ruleset) | Malformed or dangling knowledge landing on `next`; canonical entries outside canon; a canon edit without review | `--no-verify` locally; a false warrant that is well-formed; admin bypass of the ruleset; direct push to `main` (unprotected today) | this change |
| L4 | Independent check: the different-filer rule for `established` (sweep) and a human on every canon PR | A single agent self-certifying a claim | Two agents sharing one wrong source; a human who rubber-stamps | A2 (rule), this change (canon PR) |

Only L3 and L4 can fail a merge. L0 to L2 shape behaviour and are allowed to be bypassed; none of this is a security boundary, same stance as `hooks/README.md`.

## Decided

1. **Extend, do not fork.** `map.py --check` = A1 drift check + a tree lint that calls `knowledge.py` (A2) for grammar, hashing, warrant and address resolution. `map.py` adds only tree-level rules A2's per-file `check` may not cover (stage vs directory, stage vs evidence ceiling, ledger vs `done/`, frontmatter address resolution). Task 1.1 writes a table of which rule lives where and deletes any rule found in both; a rule defined twice is a bug. Finding format `E_<CODE> <path>[:<line>]: <message>`, sorted; codes `E_STAGE`, `E_SIGNAL`, `E_EDITED`, `E_WARRANT`, `E_LEDGER`, `E_ADDR` (A2 may already name some; keep A2's names and add only missing ones). The lint reads no MAP.md count; a sweep commit (signal moved to `done/`, ledger line, entry written) or a signal-filing commit leaves `--check` green because MAP.md holds nothing that those commits change.
2. **Immutability comes from git history, as A2 specifies.** `hash6` is any six hex characters, so there is no content-hash check and hand-filed signals pass. A signal file that any commit modified after the one that added it, or that is modified in the index or working tree, is `E_EDITED`; the sweep's move (rename) and a delete are not modifications. The check is A2's routine, called from `map.py`; git is used for this check only and its absence gives one notice and a skip. Limit: a pre-commit gate only sees the edit in the index, a CI run sees history; a rename-plus-edit looks like a new signal and is accepted.
3. **The ledger is checked, lightly.** Every `signals/done/*.md` has a `disposition` line in `ledger.jsonl`, and a pending file has none. Ledger line shape is A2's; the lint only needs the `signal` and `event` keys.
4. **Warrant and different-filer rule are re-derived from the entry's evidence list**, using A2's ceiling function, so a hand-edited stage fails the gate. Human-set stages (`canonical`, `superseded`, `retired`) skip the ceiling. Signals may claim any stage as a proposal, so the signal stage check is the six-value enum only. This is the only mechanical L4 check: it proves the rule held in the tree, not that two filers were independent.
5. **Addresses** are exactly A2's grammar (`K-<hash8>[#slug]`, `GUARDRAILS#G<n>`, path form) resolved by A2's resolver; the generic `path#heading-slug` form uses GitHub slug rules. Checked fields: `supersedes`, `superseded_by`, `contradicts`, `confirms`, `guardrail`, in signals and entries only, never prose. An address into `signals/`, with a leading `/` or `..` is rejected (the sweep moves signal files, so such an address dangles by design).
6. **Project reach is A2's.** Operator decision: A2 mirrors `knowledge.py` into `_common/scripts/` with a `cmp` test; this change adds no mirror and depends on A2 for it. Without `knowledge.py` the lint prints one notice and skips (feature detection, like A1's `map.py` sections). Projects get only the pre-commit gate for `map.py --check`, no CI job.
7. **Canon protection is a file, a rule and a test; no ruleset is touched.** Add `.github/CODEOWNERS` (`knowledge/canon/` owned by the operator), a PR-template checkbox, and the test that `knowledge.py apply` without `--proposal-for` cannot write canon. Operator decision: the `next` ruleset and branch protection are not hardened and not edited by this change; the test, not the ruleset, is the protection against a direct canon write.
8. **Merge-on-green exclusion.** A PR that changes anything under `knowledge/canon/` is never merged under the standing approval. Stated as an imperative block in `CLAUDE.md` (the form LEARNINGS says survives) and checked by one command in the PR template: `git diff --name-only origin/next...HEAD -- knowledge/canon`; non-empty output means a human merges. The merger (QA agent or session) runs it; no new script. Canon-proposal issues carry `knowledge` + `ready-for-human` (A2), never `ready-for-agent`, so the issue loop never picks them up.
9. **Stop hook gating: `min_profile: strict`.** Reuses the existing field; no `deploy_hooks.py` change. Alternative rejected below. No project, including the-grid, is switched to `strict` by this change.
10. **Stop hook behaviour.** Event `Stop`, no matcher, `fail: open`, timeout 5, `model_cost: false`. It reads the payload with `jq`: `stop_hook_active` (if true: exit 0, so it blocks at most once per turn) and the last assistant message (payload field if present, else the tail, at most 64 KiB, of `transcript_path`). If the message matches the claim regex and has no whole-word `RAN`, `READ` or `UNTESTED` (case-sensitive), it exits 2 with a one-line reason on stderr: `State RAN, READ or UNTESTED for each completion claim (see AGENTS_base)`. Claim regex, case-insensitive: `\b(done|complete[d]?|finished|fixed|implemented|all tests pass(ed|ing)?|tests? (are )?passing|works now|ready (for review|to merge))\b`. Missing `jq`, unreadable transcript or any parse error: exit 0. Observed 2026-10-21 against the real `claude` 2.1.x (task 3.1): the Stop payload carries `last_assistant_message` (a string) and `transcript_path` (the file exists), and its first Stop has `stop_hook_active: false`; a Stop hook that exits 2 with a one-line stderr reason feeds that reason to the model and the turn continues, and the second Stop in that turn has `stop_hook_active: true`. The transcript tail is therefore only a fallback for a payload without `last_assistant_message`.
11. **Eval cases.** Six cases, `finding: "#0"`, `expect_today: unknown` until baselined, scenarios hint-free (no case names the rule; the answer is a format-line choice, the existing style). Cost to baseline: 3 cases x 3 runs x $0.25 = $2.25 worst case per role, $4.50 for both, under the $5.00 `--max-total`.

## Alternatives rejected

- **New `opt_in: epistemics` flag** for the Stop hook: needs `OPT_INS`, project.yaml parsing and emit logic in `deploy_hooks.py`. `strict` is free and already means "more than standard".
- **Stop hook that calls a model** to judge the warrant: costs tokens on every turn and violates the repo's budget rule. The regex pair is crude on purpose; it only asks, once.
- **Hook fails closed / blocks repeatedly:** can trap a session. Fail open, one block per turn.
- **Lint of addresses in prose:** false positives on every external `file.md#x`. Frontmatter only.
- **A `scripts/canon-guard.sh`:** one `git diff --name-only` line does the job; a script adds a file to keep true.
- **Hardening `next` ruleset:** operator decision not to.
- **Eval judged by an LLM or run in the gate:** `run_evals.py` is regex-only and opt-in by design; keep it.

## Risks

1. **Lint and A2 drift apart.** A2 is still a draft and `knowledge.py` unwritten. Mitigation: import, never copy (Decided 1); task 1.6 lints A2's own signal template and the `knowledge/README.md` examples; a `cmp` test pins the seeded copies.
2. **Stop hook noise.** The regex flags chatty "done" in turns that edited nothing. Mitigation: opt-in, one block per turn, fixture test with positive and negative messages (3.3); the operator tries it on one project before keeping it.
3. **Stop hook in headless loop runs.** A block adds a turn inside a capped run (B1 caps spend and timeout). Mitigation: off by default; the loop's `loop.conf` is not touched.
4. **Evals cannot see the A1 fragment.** The lean render omits `AGENTS_base.md` and appends "Signal-file hand-offs (`signals/`) do not apply". A1 already routes lean project agents through `signals/README.md` and the trailhead; the cases here test role-owned rules only and say nothing about the fragment.
5. **Canon check is a convention.** The exclusion is read by sessions, not enforced; the operator's login bypasses the `next` ruleset (and the sweep uses that login), and `main` is unprotected. What actually keeps the sweep out of canon is that `knowledge.py apply` has no direct write path there (task 4.5 tests it). Honest label: L3 for lint, L0 plus CODEOWNERS plus a test for canon.
6. **Baselines cost money.** Task 5.3 is HUMAN and prints the worst case first.
