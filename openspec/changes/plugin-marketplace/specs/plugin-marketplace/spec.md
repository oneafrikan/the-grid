## Purpose

Offer a Claude-Code-only install channel for the-grid's own skills and composed agents as two generated plugins in a marketplace hosted by this repo, without creating any duty for third-party content and without leaking install-specific data.

## ADDED Requirements

### Requirement: Generated marketplace and bundles

The repo SHALL provide `.claude-plugin/marketplace.json` and the plugin directories `plugins/grid-core/` and `plugins/grid-agents/`, all generated by `scripts/build-plugins.py` from `plugins/bundles.json`, each plugin self-contained with `.claude-plugin/plugin.json`, `skills/<name>/SKILL.md` and `agents/*.md`.

#### Scenario: Build is deterministic and idempotent
- **WHEN** `build-plugins.py` runs twice in a row on an unchanged tree
- **THEN** the second run changes no file and `build-plugins.py --check` exits 0

#### Scenario: Drift is detected
- **WHEN** a file under `plugins/grid-core/` is edited by hand, or an owned skill listed in the manifest changes
- **THEN** `build-plugins.py --check` exits 1, names the stale path, and writes nothing

#### Scenario: Stale files are removed
- **WHEN** a skill is removed from the manifest and the build runs
- **THEN** its directory no longer exists under `plugins/grid-core/skills/`

### Requirement: Owned content only

Bundles MUST contain only skills and agents owned by the-grid (root `skills/`, root `agents/`, and composed projects `core` and `grid`) and MUST NOT include any skill from `repos/*`.

#### Scenario: Provenance guard rejects a colliding name
- **WHEN** the manifest lists a skill whose name also exists as a skill directory under `repos/*/`
- **THEN** the build exits non-zero and names the skill

#### Scenario: Missing component fails the build
- **WHEN** the manifest lists a skill with no `skills/<name>/SKILL.md`
- **THEN** the build exits non-zero and names the skill

### Requirement: No install-specific data

Generated plugin files SHALL contain no operator name or email, channel, hostname, or absolute home path.

#### Scenario: Built on a configured machine
- **WHEN** the build runs on a machine whose `agent-factory/user.yaml` has an operator email set
- **THEN** no file under `plugins/` contains that email and the output is identical to a build on a machine with no `user.yaml`

#### Scenario: Private roles do not leak
- **WHEN** `GRID_PRIVATE_ROLES_DIR` points at a roles tree that overrides a public role
- **THEN** the plugin build ignores it and emits the public role

### Requirement: Validation in the gate

`scripts/gate.sh` MUST run `build-plugins.py --check` and `claude plugin validate --strict` on the marketplace, each plugin and each plugin's `skills/` and `agents/` directory, and MUST report a skipped check loudly rather than pass silently when `claude` or the agent-factory venv is absent.

#### Scenario: Validator rejects a bad manifest
- **WHEN** a generated `plugin.json` lacks `version`
- **THEN** the gate fails on the plugins check

#### Scenario: Tool absent
- **WHEN** `claude` is not on PATH
- **THEN** the gate prints a skip notice for the validate step and lists `plugins` among skipped checks

### Requirement: Entry source paths exist

The build SHALL fail when any marketplace entry's `source` path does not exist on disk, because `claude plugin validate` does not check this.

#### Scenario: Dangling source
- **WHEN** the manifest names a bundle whose directory was not produced
- **THEN** the build exits non-zero before writing `.claude-plugin/marketplace.json`

### Requirement: Channel is secondary and documented

`docs/PLUGINS.md` MUST state that the channel is Claude-Code-only, that components are namespaced (`/grid-core:<skill>`), that third-party skills are not included, and that one install channel should be used per machine.

#### Scenario: Doc present and linked
- **WHEN** a reader opens `CLAUDE.md`
- **THEN** it points to `docs/PLUGINS.md` and `scripts/build-plugins.py`
