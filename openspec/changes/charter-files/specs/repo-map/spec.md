## Purpose

Give agents one generated, token-bounded map of what exists, how it connects and what is known, so the rest of the repo is read only when the map says to.

## ADDED Requirements

### Requirement: Generated MAP.md
`scripts/map.py` SHALL write `<root>/MAP.md` with a generated-file header and the sections Ontology, Topology and Epistemology in that order, using only Python 3 standard library (valid on 3.8), UTF-8 and `\n` newlines, code-point sorting, no timestamps and no git calls.

#### Scenario: Idempotent
- **WHEN** `python3 scripts/map.py` runs twice on an unchanged tree
- **THEN** the second run leaves `MAP.md` byte-identical

#### Scenario: Sections present
- **WHEN** `MAP.md` is generated for the-grid
- **THEN** it contains `## Ontology`, `## Topology` and `## Epistemology` in that order and the header `generated by scripts/map.py`

#### Scenario: Locale independent
- **WHEN** map.py runs with `LC_ALL=C` and again with `LC_ALL=en_US.UTF-8`
- **THEN** the two outputs are byte-identical

### Requirement: Files table with read-when
The Ontology section SHALL contain a table `| Path | What | Read when |` listing, in a fixed registry order, each registry file or directory that exists in the root, each with a non-empty read-when cell. Registry entries that do not exist SHALL be omitted.

#### Scenario: Registry coverage
- **WHEN** the root contains `PURPOSE.md`, `GUARDRAILS.md` and `signals/`
- **THEN** those three rows appear, `GUARDRAILS.md` reads "before editing, committing or opening a PR", and no row appears for `CONTEXT.md`

#### Scenario: Read-when cells
- **WHEN** any generated row is inspected
- **THEN** its Read when cell is not empty

### Requirement: Roles, skills and delegation from source
When `agent-factory/examples/*.yaml` exists, the map SHALL list role names per compose project and `delegates_to` per orchestrator, derived from those files; when `skills/*/SKILL.md` or `.claude/skills/*/SKILL.md` exist it SHALL list skill names. Sections whose source directory is absent SHALL be omitted.

#### Scenario: Role count matches configs
- **WHEN** map.py runs on the the-grid root
- **THEN** the number of role names listed equals `grep -h '^[[:space:]]*- role:' agent-factory/examples/*.yaml | wc -l`

#### Scenario: Project without agent-factory
- **WHEN** map.py runs on a root with no `agent-factory/`
- **THEN** MAP.md has no Roles or Delegation content and exits 0

### Requirement: No volatile data in MAP.md
`MAP.md` SHALL contain no stage counts, no pending-signal counts and no other number that changes when a signal is filed or processed or when a non-canon knowledge entry is added, edited or moved. It SHALL contain a static line pointing to `python3 scripts/map.py status` for those counts.

#### Scenario: Signal commit leaves the map current
- **WHEN** a knowledge signal is added to `signals/`, or moved to `signals/done/`, or a `wip` entry is added under `knowledge/`
- **THEN** `python3 scripts/map.py --check` still exits 0 without regenerating

#### Scenario: Canon change needs regeneration
- **WHEN** a file is added to `knowledge/canon/`
- **THEN** `--check` exits 1 until `python3 scripts/map.py` regenerates `MAP.md`

### Requirement: Canon lines
The Epistemology section SHALL list one line per file in `knowledge/canon/` (excluding `.gitkeep` and `README.md`) as `- <claim> (knowledge/canon/<file>)`, sorted by file name, at most 20, followed by `+N more: knowledge/canon/` when there are more. `<claim>` is the frontmatter `claim` (or, with none, the first non-empty body line), whitespace-collapsed and truncated to 140 characters ending `...`.

#### Scenario: Empty knowledge
- **WHEN** `knowledge/` holds only `README.md` and `canon/.gitkeep`
- **THEN** no canon lines appear

#### Scenario: Canon cap
- **WHEN** `knowledge/canon/` holds 23 entries
- **THEN** exactly 20 canon lines appear followed by `+3 more: knowledge/canon/`

#### Scenario: One-liner
- **WHEN** a canon entry's `claim` is longer than 140 characters
- **THEN** its line carries the first 140 characters, whitespace collapsed, ending `...`

### Requirement: Status subcommand
`python3 scripts/map.py status [--root DIR]` SHALL print one count for each of the six stages `wip`, `provisional`, `established`, `canonical`, `superseded`, `retired`, taken from the `stage` frontmatter of `knowledge/**/*.md` (excluding `README.md`), a line `invalid: N` when any entry has a missing or unknown stage, and `pending signals: N` counting `signals/*.md` except `README.md` and names starting `→`. It SHALL write no file, exit 0, and not be run by `--check` or the gate.

#### Scenario: Empty repo
- **WHEN** `knowledge/` holds no entries and `signals/` holds only `README.md`
- **THEN** all six counts are 0, `pending signals: 0`, and no `invalid` line appears

#### Scenario: Handoffs not counted
- **WHEN** `signals/` holds one `→qa.md`, one knowledge signal and `README.md`
- **THEN** `pending signals: 1`

#### Scenario: Unknown stage
- **WHEN** an entry has `stage: maybe`
- **THEN** it is counted under `invalid: 1` and in no stage count

#### Scenario: Writes nothing
- **WHEN** `status` runs on a read-only copy of the tree
- **THEN** it exits 0 and no file changes

### Requirement: Sweep status line
The Topology section SHALL name the sweep as `gh-triage knowledge sweep` only when `agent-factory/roles/gh-triage/AGENTS.md` contains a heading `Knowledge sweep`, otherwise `none configured`.

#### Scenario: No sweep yet
- **WHEN** map.py runs before `knowledge-signals` has shipped
- **THEN** the sweep line reads `none configured`

### Requirement: Memory statement
The Epistemology section SHALL state which memory is always in context (CLAUDE.md learnings summary, up to 6 instincts when `learning: on`, canon lines in MAP.md) and which is on demand only (`LEARNINGS.md`, `knowledge/` below canon).

#### Scenario: Text present
- **WHEN** MAP.md is generated
- **THEN** it contains the words "Always in context" and "On demand"

### Requirement: Drift check
`python3 scripts/map.py --check` SHALL write nothing and exit 0 when `MAP.md` equals the freshly generated text, 1 when it differs or is missing (printing `run: python3 scripts/map.py`), and 2 when it could not compare. It SHALL perform no validation beyond that comparison (stage-enum, signal and address validation belong to `epistemic-enforcement`, which extends this requirement).

#### Scenario: Current
- **WHEN** MAP.md was just generated
- **THEN** `--check` exits 0 and modifies no file

#### Scenario: Stale
- **WHEN** a new file `CONTEXT.md` is added without regenerating
- **THEN** `--check` exits 1 and prints the regenerate command

#### Scenario: Missing
- **WHEN** MAP.md does not exist
- **THEN** `--check` exits 1

#### Scenario: Unknown flag or argument
- **WHEN** `map.py --chek` or `map.py frobnicate` runs
- **THEN** it exits 2 and writes no file

### Requirement: Token budget
`MAP.md` SHALL NOT exceed 150 lines or 12 000 bytes; when generation would exceed either, map.py SHALL exit 2 naming the limit and SHALL NOT write the file.

#### Scenario: the-grid fits
- **WHEN** MAP.md is generated for the the-grid root
- **THEN** it is within both limits

#### Scenario: Over budget
- **WHEN** a fixture root yields more than 150 lines
- **THEN** map.py exits 2 and no `MAP.md` is written or changed

### Requirement: Gate wiring and mirror
`scripts/gate.sh` SHALL run `python3 scripts/map.py --check` as a check named `map`, recording it as skipped when `python3` or the script is absent. `project-factory/templates/_common/scripts/map.py` SHALL be byte-identical to `scripts/map.py`.

#### Scenario: Gate fails on drift
- **WHEN** MAP.md is stale
- **THEN** `bash scripts/gate.sh` reports `map` FAIL

#### Scenario: Gate skip is recorded
- **WHEN** `python3` is hidden from PATH
- **THEN** the gate summary's skipped list contains `map`

#### Scenario: Mirror
- **WHEN** the two copies are compared with `cmp`
- **THEN** they are identical
