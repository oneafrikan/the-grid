the-grid

Inspired by Tron. Dotfiles for your AI assistant: curated skills and agent teams, wired identically onto every machine and every AI tool you use.

git clone https://github.com/oneafrikan/the-grid.git ~/.the-grid && bash ~/.the-grid/scripts/bootstrap.sh --with-agents

View on GitHub Star on GitHub Quickstart

Works today with Claude Code. Other AI tools: see docs/roadmap.md.

Who it's for

  • You use more than one machine (laptop, server, work, home) and your Claude Code setup keeps drifting between them.
  • You collect skills from many repos and installing everything buries your session. You want a short live list and a searchable shelf.
  • You build agent teams (tech lead, QA, security reviewer) and want each role defined once and wired the same everywhere.
  • Not for you if you want a supported product, a GUI or a one-click installer. I built this for my own machines and share it because the mechanics are reusable.

Quickstart

Run the command in the header (the Copy button, or click it to select it all). It needs git, bash, python3 (for the agent teams) and Claude Code. Node >= 20.19 only if you use the openspec-* skills (see INSTALL.md).

You should now see:

  • bootstrap.sh ends with ==> Bootstrap complete. Open a fresh Claude session to pick up new skills/agents.
  • ls ~/.claude/skills | wc -l prints a number near 132 (plus the orchestrator skills; duplicate skill names across repos collapse to one link, so it is not exact), and ls ~/.claude/skills/tron lists a SKILL.md.
  • In a new Claude Code session /tron replies with a short question about what you want to do.

Fork first if you plan to customise: the clone URL in the header is read-only for you.

Or paste this into Claude:

Clone https://github.com/oneafrikan/the-grid.git to ~/.the-grid, run bash ~/.the-grid/scripts/bootstrap.sh --with-agents, tell me what it printed, then tell me to open a fresh session and run /tron.

Stop there. If it felt useful, read USAGE.md. Prefer the manual steps, or a machine without submodules? See INSTALL.md.

What you get

  • 40 ready-made agent roles: a dev team, a finance desk, a Socratic tutor (/morpheus), and /tron, which tells you which one to use.
  • One git pull plus wire.sh makes every machine identical; a per-machine overlay handles the differences.
  • Project templates with specs and agents already wired in.

How it works

  • Wired vs library. Only repos on the allowlist are symlinked live. Everything else is indexed in SKILLS.md and found with /skill-scout.
  • Per-machine overlay. A shared baseline plus an optional machines/<host>.txt adds or removes entries for one machine.
  • Symlinks, not copies. Edit a skill once and every wired copy changes. A skill in skills/ overrides a same-named upstream one.
  • Agents compiled from one source. compose.py builds each role from role x stack x skills; wire.sh links the result.

Four sibling pieces produce the assets: agent-factory/ (agent teams), automation-factory/ (reusable automation patterns), project-factory/ (project templates) and the skill wiring itself. The layout, every script and the full wire.sh sequence are in docs/architecture.md.

agent-factory — composed agents

agent-factory/ composes AI dev-team agents from three orthogonal inputs: role × stack × skills. Each input is independent — swap a stack overlay without touching the role's identity, or bolt on a skill without rewriting anything else.

role

Who the agent is — Tech Lead, Backend Dev, QA, and so on. Stack-agnostic identity, personality, and an operating skill. Lives in roles/<role>/.

stack

What it builds on — LAMP, modern-frontend, data-engineering…. An overlay appended to the role's operating rules. Lives in stacks/<stack>/.

skills

Bolt-on capabilities pulled from the ecosystem (Paperclip, php, mysql…). Referenced by name — not copied into the agent output.

A compose config names a project and lists agents, each as role + stacks[] + skills[] + model. compose.py reads it and emits one folder per agent under agent-factory/projects/<name>/, rendered to the live OpenClaw 5-file identity model: SOUL.md (how it behaves), IDENTITY.md (who it is + model), AGENTS.md (boot sequence + async handoff), USER.md (who it serves), MEMORY.md (what it carries).

compose.py is a multi-target compiler — one 5-file source, a different artefact shape per --target. The claude-code target splits on role.yaml orchestrator:

Form Roles How to invoke
Skill (orchestrator) grid-ceo-orchestrator, grid-tech-lead, grid-growth-hacker, finance-desk-finance-manager, tron, morpheus, oracle Slash command — /grid-tech-lead. Transforms the session into that role.
Subagent (specialist) the other roles Not a slash command. Delegate: "Use the grid-backend-dev subagent to…", or let an orchestrator hand off automatically.

The very agents that maintain the-grid — the Tech Lead orchestrator and the Frontend, Backend, and QA specialists — are themselves output of agent-factory. The Claude Code target is the one built and wired live; the other --target values are listed under Roadmap.

automation-factory — reusable patterns

A sibling factory to agent-factory/, one tier down: not composed agents, but reusable automation patterns — the orchestration layer that wires an agent into a recurring, unattended workflow. A tailor doesn't sew each suit from scratch — they cut from a pattern. Each pattern is a generic, version-controlled template, instantiated (cut + placeholder-filled) into a target repo's tracked loop/ folder — not .claude/, which is commonly gitignored and wouldn't survive a clone or repo move.

First pattern: issue-loop — an agent that works a repo's labelled GitHub issues and hands a verified pull request to a human, one issue per run. Composes a headless runner with a /loop prompt and a post-commit review hook.

The template is what the-grid owns; the instance lives in the project it serves. scripts/instantiate.sh <pattern> <target-repo> --profile <personal|work|mac-mini> does the profiled cut: a verbatim copy into loop/, a loop.conf rendered once, and on the work and mac-mini profiles the headless runner (one issue per run; it runs your verify command itself and opens a PR, never a merge) with a push guard and a worktree helper.

project-factory — project bootstrapping

Scaffolds whole new projects from a template — a different job from skills/ (wired), agent-factory/ (composes personas), and automation-factory/ (cuts a pattern into an existing repo). A template is standalone: no logic of its own, doesn't run, doesn't depend on the-grid once cut.

project-factory/scripts/cut-project.sh <template> <target-dir> either seeds a brand-new project (empty target) or retrofits an existing one (non-empty target) — same script, same rule either way: never overwrite a file that already exists and differs from the template; anything skipped is reported for manual review. Composition (which agent-factory persona, which skills, which automation-factory pattern) happens after seeding, as a normal step in the resulting repo.

Agents

agent-factory produces 40 roles across four independently composed and gated public projects (plus any private desk composed the same way, sourcing roles from outside this repo — see docs/private-projects.md). Some roles are orchestrators — they become Claude Code skills invoked as slash commands; some coordinate a team (one, gsd, is the light fan-out for small fixes), and three (tron, morpheus, oracle) talk to you directly. The rest are specialists — subagents delegated to by an orchestrator or called directly.

core cross-desk infra — stays wired everywhere

core-gh-triage specialist
GitHub Triage Agent

Scheduled GitHub issue triage — classifies severity, applies mattpocock labels, writes agent briefs for machine-doable issues and triage notes for human-required ones. Cron-driven, no delegation chain.

core-librarian specialist
Librarian

Maintains persistent, cross-linked markdown wikis compiled from other agents' research — one wiki per domain. Runs the ingest / query / lint cycle, preserving every page's evidence tier and provenance. Never asserts a claim itself.

core-context-engineer specialist
Context Engineer

Designs and measures what loads into a session and when: size and split, cache-friendly ordering, retrieval design, compaction and handoff. Measures before and after; shows the diff before touching a human's CLAUDE.md or memory.

core-platform-engineer specialist
Platform Engineer

Makes a personal developer environment — dotfiles, shell functions, bootstrap scripts, per-machine overlays — work on macOS, Ubuntu and Arch from one repo. Small, dry-run-verified changes on a branch; the human tests the other OSes and decides on merge.

core-researcher specialist
Researcher

Desk, web, market, competitive and technical research. Source-grounded, fact-checked synthesis with citations. Investigates a question; does not decide.

tron orchestrator
Tron — the front door

Run /tron first. Asks what you are trying to do, checks which skills and agents are actually wired on this machine, and recommends the right one with a reason and a next step. Recommends and hands off; never does the work or launches anything without your yes.

finance-desk standalone — not part of the CEO's chain

finance-desk-finance-manager orchestrator
Finance Manager

Orchestrates the finance desk pipeline (sentinel → analyst → strategist → risk-officer → approval → scribe). Routes and grades escalation; never sizes a trade, never overrides the Risk Officer, never auto-approves. Standalone — deliberately outside the CEO's delegation chain.

finance-desk-finance-sentinel specialist
Finance Sentinel

Polls prices, portfolio state, RSS/filings, and FX against threshold rules. 95% deterministic; the model only classifies and flags. Never analyses, never recommends.

finance-desk-finance-analyst specialist
Finance Analyst

Turns a Sentinel flag (or scheduled review) into an evidence pack: what happened, primary sources, base rates, and the bull AND bear case argued with equal effort. Never recommends — output is evidence, not a proposal.

finance-desk-finance-strategist specialist
Finance Strategist

Reads an evidence pack + the Investment Policy + portfolio state and produces a proposal (hold/trim/add/rebalance) with position size, an explicit confidence level, and the strongest argument against its own proposal.

finance-desk-finance-risk-officer specialist
Finance Risk Officer

Layer-2 sanity check: verifies the Strategist's arithmetic and checks the proposal against the Investment Policy's text. The hard-limit veto (position caps, drawdown circuit breaker, no leverage) is Layer-1 pure code elsewhere, not this agent.

finance-desk-finance-scribe specialist
Finance Scribe

Logs every flag, brief, proposal, approval/rejection, and outcome to the vault with full rationale. Runs the monthly post-mortem. Never proposes or judges — records only.

learning-desk manual — you start every session; data stays private

morpheus orchestrator
Morpheus — Socratic tutor

Teaches any topic you choose as an interactive course: syllabus, one lesson at a time, questions before answers, one exercise per lesson, section quizzes, a final challenge. Moves on only when you have shown you understand. Teaches only; logs what you learned.

oracle orchestrator
Oracle — learns about you

Interviews you and reads only the files you approve, then keeps a private profile you can edit or delete: how you work, your goals, strengths and gaps, and the name, role and avatar you pick for yourself. Every entry is tagged stated, observed or inferred.

tank specialist
Tank — agent-to-agent learning

On request, reads the run log and transcripts you name, finds what an agent got right or wrong, and writes a lesson plus a proposed change to that role's guidance. Proposes only; you review and apply it.

Skills

132 skills are wired live and active in every Claude session. Another 100 are indexed but switched off, searchable with /skill-scout. The full, generated list is SKILLS.md.

Specs — spec-driven development

the-grid wires OpenSpec (Fission-AI/openspec, MIT) on every machine — the openspec-* skills covering explore → propose → apply → verify → archive. Specs live in the repo as plain markdown, so a plan outlives the session that produced it, and a proposal gets reviewed before any code exists.

There is deliberately no fifth factory here. OpenSpec already is the spec factory; rebuilding propose/apply/archive would be reimplementing it badly. the-grid adds two thin layers instead:

  • project-factory/templates/_common/SPECS.md — the convention plus agent instructions, laid down on every cut project, seed or retrofit. Spec-driven becomes the default rather than a per-project decision someone has to remember to make.
  • agent-factory/_core/AGENTS_base.md — a boot-sequence check for SPECS.md / openspec/. One edit reaches every composed agent. Conditional: repos without those markers are untouched.

/openspec-help is the reference card. /spec-scout audits adoption and reports drift between the specs and what the code actually does — survey-only, it never writes a spec.

External dependency. These skills shell out to a CLI that isn't vendored, and pull their real instructions from it at runtime — without it they load and dead-end immediately: npm install -g @fission-ai/openspec@1.12.0 (needs Node ≥ 20.19.0). openspec init is optional — openspec new change bootstraps the openspec/ tree on its own.

Roadmap

Shipped: the Claude Code target is built and wired live. compose.py --target also accepts openclaw, openclaw-native, paperclip, codex, gemini-cli, opencode and portable (single-file personas committed under dist/personas/). Skills, subagents and rule packs reach Codex CLI, OpenCode and Gemini CLI through opt-in harness:<name> manifest entries (docs/harnesses.md); Cursor gets rule packs only (scripts/rules.py emit --harness cursor), not an agent target.

Status & expectations

This is one person's working system, shared because the mechanics are reusable, not a supported product.

  • It will change under you. Versioned from v0.1.0; v0.x may still break between tags.
  • It is opinionated. The wiring model, the factories and the compose format are my choices, not a consensus design.
  • Personal config is gitignored, not mixed in. baseline-submodules.txt, machines/<host>.txt and the dev-journal LOGS/ convention are personal and untracked. You get a generic .example starting point for the first two and owe nothing for the third. A fork never inherits my machine names, account routing or notes.
  • Fork rather than depend. The wiring model (manifest, symlinks, compose-then-wire) is the transferable part. Copy it and point it at your own skills.
  • wire.sh mostly writes symlinks that point into this repo, but not only. It never clobbers a real directory or a foreign symlink in ~/.claude/skills/. It also keeps one auto-handoff hook entry in ~/.claude/settings.json (on by default; opt out with -hook:auto-handoff). With opt-in entries it links rule packs under ~/.claude/rules/grid/ and other harness directories. Inside the clone it writes .wired.manifest and SKILLS.md. The full list is in INSTALL.md ("What it touches"). Read the script before running it; it writes to your home directory.
