the-grid

The Grid. A digital frontier. I tried to picture clusters of information as they moved through the computer. What did they look like? Ships? Motorcycles? Were the circuits like freeways? I kept dreaming of a world I thought I’d never see. And then, one day… I got in.

What it is

the-grid is not a framework and not skills-only. It wires skills from across the ecosystem, and it composes and wires AI dev-team agents. Agents, machines, MCP servers, prompts, and configs are already growing in.

The core mechanic: a single script (wire.sh) symlinks skills and composed agents into ~/.claude/skills/ and ~/.claude/agents/ so Claude picks them up automatically — no installs, no config files. the-grid owns some assets directly and pulls many more from sibling repos via git submodules.

The two tiers

Wired live

Repos in baseline-submodules.txt (every machine) plus an optional per-machine overlay at machines/<host>.txt. Their skills are symlinked live into ~/.claude/skills/ and active in every session. Keep the baseline small and intentional.

Library indexed

Everything else: indexed in SKILLS.md and searchable via skill-scout, but not symlinked. Keeps the active set sane even as the-grid indexes thousands of ecosystem skills. Promote to wired by adding to the allowlist.

Reference browse

Awesome-lists and indexes with no SKILL.md files. Kept for browsing and as a source for skill-scout. Nothing to wire; catalog.sh auto-detects and lists them separately.

Ownership rule: root-level dirs are for skills Gareth owns or has deliberately forked. Everything else is managed upstream in repos/* submodules and wired on demand. When a root dir and a submodule share the same skill name, the root copy wins — that's the escape hatch for an edited fork. Don't copy an upstream skill to the root just to use it; add the repo as a submodule instead.

agent-factory — composed agents

agent-factory/ composes AI dev-team agents from three orthogonal inputs: role × stack × skills. Each input is independent — swap a stack overlay without touching the role's identity, or bolt on a skill without rewriting anything else.

role

Who the agent is — Tech Lead, Backend Dev, QA, and so on. Stack-agnostic identity, personality, and an operating skill. Lives in roles/<role>/.

stack

What it builds on — LAMP, modern-frontend, data-engineering…. An overlay appended to the role's operating rules. Lives in stacks/<stack>/.

skills

Bolt-on capabilities pulled from the ecosystem (Paperclip, php, mysql…). Referenced by name — not copied into the agent output.

A compose config names a project and lists agents, each as role + stacks[] + skills[] + model. compose.py reads it and emits one folder per agent under agent-factory/projects/<name>/, rendered to the live OpenClaw 5-file identity model: SOUL.md (how it behaves), IDENTITY.md (who it is + model), AGENTS.md (boot sequence + async handoff), USER.md (who it serves), MEMORY.md (what it carries).

compose.py is a multi-target compiler — one 5-file source, a different artefact shape per --target. The claude-code target splits on role.yaml orchestrator:

Form Roles How to invoke
Skill (orchestrator) grid-ceo-orchestrator, grid-tech-lead, grid-growth-hacker, finance-desk-finance-manager Slash command — /grid-tech-lead. Transforms the session into that role.
Subagent (specialist) the other 24 roles Not a slash command. Delegate: "Use the grid-backend-dev subagent to…", or let an orchestrator hand off automatically.

Compose a team and wire it into Claude Code

# Compose each public project for the Claude Code target
.venv/bin/python agent-factory/compose.py agent-factory/examples/core.yaml --target claude-code
.venv/bin/python agent-factory/compose.py agent-factory/examples/grid.yaml --target claude-code
.venv/bin/python agent-factory/compose.py agent-factory/examples/finance-desk.yaml --target claude-code

# Wire the output — orchestrators → ~/.claude/skills/, specialists → ~/.claude/agents/
bash scripts/wire.sh

# Open a fresh Claude Code session to pick up the new agents, then:
# /grid-tech-lead    ← invoke the orchestrator
The very agents that maintain the-grid — the Tech Lead orchestrator and the Frontend, Backend, and QA specialists — are themselves output of agent-factory. The Claude Code target is live today; OpenClaw and Paperclip (autonomous) targets are the next work.

automation-factory — reusable patterns

A sibling factory to agent-factory/, one tier down: not composed agents, but reusable automation patterns — the orchestration layer that wires an agent into a recurring, unattended workflow. A tailor doesn't sew each suit from scratch — they cut from a pattern. Each pattern is a generic, version-controlled template, instantiated (cut + placeholder-filled) into a target repo's tracked loop/ folder — not .claude/, which is commonly gitignored and wouldn't survive a clone or repo move.

First pattern: issue-loop — an autonomous agent that works a repo's GitHub issue backlog unattended, with an auto code-review posted to each issue. Composes a /loop prompt with a post-commit review hook.

The template is what the-grid owns; the instance lives in the project it serves. scripts/instantiate.sh (planned, see TODO.md issue #15) will add a machine-profiled cut: copy into loop/ + placeholder-fill + settings wiring, plus worktree/PR sandboxing and launchd vs cloud scheduling.

project-factory — project bootstrapping

Scaffolds whole new projects from a template — a different job from skills/ (wired), agent-factory/ (composes personas), and automation-factory/ (cuts a pattern into an existing repo). A template is standalone: no logic of its own, doesn't run, doesn't depend on the-grid once cut.

scripts/cut-project.sh <template> <target-dir> either seeds a brand-new project (empty target) or retrofits an existing one (non-empty target) — same script, same rule either way: never overwrite a file that already exists and differs from the template; anything skipped is reported for manual review. Composition (which agent-factory persona, which skills, which automation-factory pattern) happens after seeding, as a normal step in the resulting repo.

Agents

agent-factory produces 28 roles across three independently composed and gated public projects (plus any private desk composed the same way, sourcing roles from outside this repo — see CLAUDE.md). Four roles are orchestrators — they become Claude Code skills invoked as slash commands and can coordinate the rest of their team. The other 24 are specialists — subagents delegated to by an orchestrator or called directly.

core cross-desk infra — stays wired everywhere

core-gh-triage specialist
GitHub Triage Agent

Autonomous GitHub issue triage — classifies severity, applies mattpocock labels, writes agent briefs for machine-doable issues and triage notes for human-required ones. Cron-driven, no delegation chain.

Librarian

Maintains persistent, cross-linked markdown wikis compiled from other agents' research — one wiki per domain. Runs the ingest / query / lint cycle, preserving every page's evidence tier and provenance. Never asserts a claim itself.

finance-desk standalone — not part of the CEO's chain

finance-desk-finance-manager orchestrator
Finance Manager

Orchestrates the finance desk pipeline (sentinel → analyst → strategist → risk-officer → approval → scribe). Routes and grades escalation; never sizes a trade, never overrides the Risk Officer, never auto-approves. Standalone — deliberately outside the CEO's delegation chain.

finance-desk-finance-sentinel specialist
Finance Sentinel

Polls prices, portfolio state, RSS/filings, and FX against threshold rules. 95% deterministic; the model only classifies and flags. Never analyses, never recommends.

finance-desk-finance-analyst specialist
Finance Analyst

Turns a Sentinel flag (or scheduled review) into an evidence pack: what happened, primary sources, base rates, and the bull AND bear case argued with equal effort. Never recommends — output is evidence, not a proposal.

finance-desk-finance-strategist specialist
Finance Strategist

Reads an evidence pack + the Investment Policy + portfolio state and produces a proposal (hold/trim/add/rebalance) with position size, an explicit confidence level, and the strongest argument against its own proposal.

finance-desk-finance-risk-officer specialist
Finance Risk Officer

Layer-2 sanity check: verifies the Strategist's arithmetic and checks the proposal against the Investment Policy's text. The hard-limit veto (position caps, drawdown circuit breaker, no leverage) is Layer-1 pure code elsewhere, not this agent.

finance-desk-finance-scribe specialist
Finance Scribe

Logs every flag, brief, proposal, approval/rejection, and outcome to the vault with full rationale. Runs the monthly post-mortem. Never proposes or judges — records only.

Key files

File / dir Purpose
agent-factory/ Composes dev-team agents from role × stack × skills. compose.py is the multi-target compiler — one 5-file source, different artefact per --target. wire.sh wires the output live.
automation-factory/ Reusable automation patterns (e.g. issue-loop), cut into a target repo's tracked loop/ folder.
project-factory/ Scaffolds whole new projects from a template via scripts/cut-project.sh (seed or retrofit).
scripts/wire.sh The wiring script. Idempotent — tears down all grid-owned symlinks and rebuilds the wired set each run.
baseline-submodules.txt Baseline allowlist of submodules whose skills are wired live on every machine. Anything not listed is library-only.
machines/<host>.txt Per-machine overlay layered on the baseline — adds or subtracts entries for that host only.
scripts/catalog.sh Regenerates SKILLS.md. Deterministic, timestamp-free output. Called automatically by wire.sh.
SKILLS.md Generated index of the whole ecosystem. Never edit by hand.
scripts/reconcile.sh Removes stale shadowing dirs on a fresh machine so the-grid owns the slot, then re-wires.
tests/ Bats test suite covering wiring, idempotency, skill format, and submodule health.
repos/ Sibling skill repos as git submodules. Each may contain many skill dirs at any nesting depth.

Common commands

Bootstrap a new machine

git clone https://github.com/<your-username>/the-grid.git ~/.the-grid \
  && bash ~/.the-grid/scripts/bootstrap.sh
# add --with-agents to also compose + wire the agent team in the same run

Check grid health

bash scripts/check-grid.sh
# runs the bats suite + scans for broken grid-owned symlinks; exits non-zero on failure

Add a skill

mkdir ~/.the-grid/skills/my-skill
# create SKILL.md with name: and description: frontmatter
bash scripts/wire.sh

Regenerate the skill catalogue

bash scripts/catalog.sh
# wire.sh calls this automatically — rarely needed standalone

Add a sibling repo (library by default)

git submodule add <repo-url> repos/<name>
git submodule update --init
bash scripts/wire.sh
# To wire it live everywhere: add repos/<name> to baseline-submodules.txt, then re-run wire.sh
# To wire it on one machine only: add it to machines/<host>.txt instead

Cut a new project from a template

bash project-factory/scripts/cut-project.sh <template> <target-dir>
# seeds an empty target, or retrofits a non-empty one — never overwrites a differing file

Reconcile stale shadows on a fresh machine

bash scripts/reconcile.sh          # dry run — list shadowing dirs
bash scripts/reconcile.sh --force  # remove + re-wire

Run tests

tests/lib/bats-core/bin/bats tests/
